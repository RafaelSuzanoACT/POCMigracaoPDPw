## Summary

This plan defines the technical architecture and implementation strategy for migrating 142 ASPX pages from ASP.NET WebForms to React + Vite. The migration prioritizes 7 critical routines (14 pages) essential for Brazil's national energy scheduling operations. Current status: 34 pages migrated (23.9%), 0% backend connected. Target: 100% migration with 100% test coverage and full backend integration.

**Primary Technical Approach:**
- **Frontend Stack**: React 18+ with Vite 5.x, TypeScript 5.x
- **Data Management**: React Query (TanStack Query) for server state, Zustand for client state
- **Testing**: Vitest + React Testing Library for unit tests, Playwright for E2E tests
- **Architecture**: Layered (UI Components → Data Hooks → Service Layer → Backend APIs)
- **Quality Gates**: 100% test coverage, WCAG 2.1 AA accessibility, responsive design, visual parity with legacy

## Layered Architecture Details

### Architecture Overview

The frontend follows a strict 3-layer architecture to ensure separation of concerns, testability, and maintainability:

```
┌─────────────────────────────────────────────────────────────┐
│                     PRESENTATION LAYER (UI)                  │
│  - React functional components with hooks                    │
│  - CSS Modules for styling                                   │
│  - No business logic, no direct API calls                    │
│  - Receives data via props from hooks                        │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    DATA MANAGEMENT LAYER                     │
│  - React Query hooks (useEnergeticData, useSaveEnergetic)   │
│  - Zustand stores (auth, app state)                          │
│  - Custom composition hooks                                  │
│  - Caching, synchronization, optimistic updates             │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                       SERVICE LAYER                          │
│  - Axios-based HTTP clients                                  │
│  - API endpoint definitions                                  │
│  - Request/response transformations (DTOs)                   │
│  - Error normalization                                       │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    BACKEND APIs (.NET 8)                     │
│  - ONS_PoC-PDPW_V2 repository                                │
│  - REST APIs with JSON responses                             │
│  - SQL Server database                                       │
└─────────────────────────────────────────────────────────────┘
```

### Layer 1: Presentation (UI Components)

**Responsibility**: Render UI, handle user interactions, display data

**Rules**:
- Functional components only (no class components)
- Use hooks for state and side effects
- Receive data via props (from parent or hooks)
- **NEVER** call APIs directly (always use service layer + hooks)
- **NEVER** contain business logic (calculations, validation rules)
- Use CSS Modules for styling (e.g., `Component.module.css`)
- All interactive elements have `data-testid` attributes

**Example Pattern**:
```typescript
// src/pages/Collection/Energetic/Energetic.tsx
import { useEnergeticData, useSaveEnergetic } from '@/hooks';
import { Grid48Intervals } from '@/components/domain/Grid48Intervals';

export const Energetic: React.FC = () => {
  const { data, isLoading, error } = useEnergeticData();
  const { mutate: save, isLoading: isSaving } = useSaveEnergetic();
  
  const handleSave = (values: EnergeticData) => {
    save(values);
  };
  
  if (isLoading) return <Spinner data-testid="loading-spinner" />;
  if (error) return <ErrorMessage data-testid="error-message" error={error} />;
  
  return (
    <div className={styles.container} data-testid="energetic-container">
      <h1 data-testid="page-title">Programação Energética</h1>
      <Grid48Intervals 
        data={data}
        onSave={handleSave}
        isSaving={isSaving}
        data-testid="grid-48-intervals"
      />
    </div>
  );
};
```

### Layer 2: Data Management (Hooks)

**Responsibility**: Manage server state, caching, mutations, client state

**React Query Hooks** (for server state):
- **Query hooks**: Fetch and cache data from backend
  - Pattern: `use<Entity>Data` (e.g., `useEnergeticData`, `useElectricalData`)
  - Handle loading states, errors, refetching, caching
  - Automatic background refetching and invalidation
  
- **Mutation hooks**: Modify data on backend
  - Pattern: `useSave<Entity>` or `use<Action><Entity>` (e.g., `useSaveEnergetic`, `useDeleteOffer`)
  - Handle optimistic updates
  - Invalidate related queries on success

**Zustand Stores** (for client state):
- **authStore**: User authentication state (token, user info, permissions)
- **appStore**: Application state (loading flags, error messages, notifications)

**Custom Composition Hooks**:
- Combine multiple React Query hooks
- Encapsulate complex state logic
- Pattern: `use<Feature>` (e.g., `use48IntervalGrid`, `useFilteredDataGrid`)

**Example Pattern**:
```typescript
// src/hooks/useEnergeticData.ts
import { useQuery } from '@tanstack/react-query';
import { energeticService } from '@/services';

export const useEnergeticData = (date: string, companyId: string) => {
  return useQuery({
    queryKey: ['energetic', date, companyId],
    queryFn: () => energeticService.getData(date, companyId),
    enabled: !!date && !!companyId,
    staleTime: 5 * 60 * 1000, // 5 minutes
    cacheTime: 10 * 60 * 1000, // 10 minutes
  });
};

// src/hooks/useSaveEnergetic.ts
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { energeticService } from '@/services';

export const useSaveEnergetic = () => {
  const queryClient = useQueryClient();
  
  return useMutation({
    mutationFn: energeticService.save,
    onSuccess: (data, variables) => {
      // Invalidate and refetch
      queryClient.invalidateQueries(['energetic', variables.date, variables.companyId]);
      
      // Optionally update cache directly (optimistic update)
      queryClient.setQueryData(['energetic', variables.date, variables.companyId], data);
    },
    onError: (error) => {
      // Handle error (toast notification, etc.)
      console.error('Error saving energetic data:', error);
    },
  });
};
```

### Layer 3: Service Layer (HTTP Clients)

**Responsibility**: Communicate with backend APIs, transform data, handle errors

**Rules**:
- One service file per domain entity (e.g., `energeticService.ts`, `electricalService.ts`)
- All HTTP calls use centralized Axios instance (`src/services/api.ts`)
- Transform backend DTOs to frontend types
- Normalize errors to consistent format
- **NO** React dependencies (services are pure TypeScript)

**Centralized Axios Instance**:
```typescript
// src/services/api.ts
import axios from 'axios';
import { authStore } from '@/store/authStore';

const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || 'http://localhost:5001/api',
  timeout: 30000,
  headers: {
    'Content-Type': 'application/json',
  },
});

// Request interceptor: Add auth token
api.interceptors.request.use((config) => {
  const token = authStore.getState().token;
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// Response interceptor: Handle errors globally
api.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      authStore.getState().logout();
      window.location.href = '/auth/login';
    }
    return Promise.reject(error);
  }
);

export default api;
```

import type { EnergeticData, EnergeticRequestDto, EnergeticResponseDto } from '@/types/energetic';

export const energeticService = {
  async getData(date: string, companyId: string): Promise<EnergeticData> {
    const response = await api.get<EnergeticResponseDto>('/energetic', {
      params: { date, companyId },
    });
    
    // Transform backend DTO to frontend type
    return transformEnergeticResponse(response.data);
  },
  
  async save(data: EnergeticData): Promise<EnergeticData> {
    const dto: EnergeticRequestDto = transformToRequestDto(data);
    const response = await api.post<EnergeticResponseDto>('/energetic', dto);
    return transformEnergeticResponse(response.data);
  },
  
  async delete(id: string): Promise<void> {
    await api.delete(`/energetic/${id}`);
  },
};

// DTO transformations
function transformEnergeticResponse(dto: EnergeticResponseDto): EnergeticData {
  return {
    id: dto.id,
    date: dto.data,
    company: dto.empresa,
    intervals: dto.intervalos.map((i) => ({
      time: i.horario,
      value: i.valor,
      total: i.total,
    })),
    // ... more transformations
  };
}

function transformToRequestDto(data: EnergeticData): EnergeticRequestDto {
  return {
    id: data.id,
    data: data.date,
    empresa: data.company,
    intervalos: data.intervals.map((i) => ({
      horario: i.time,
      valor: i.value,
      total: i.total,
    })),
    // ... more transformations
  };
}

## Definition of Done (DoD)

### Page Migrated (Frontend Only)

A page is considered "migrated" when ALL of the following criteria are met:

1. ✅ React component created in `frontend/src/pages/<Module>/<Subdomain>/`
2. ✅ CSS Module created preserving legacy visual identity
3. ✅ TypeScript types defined in `src/types/`
4. ✅ Unit tests created in `tests/pages/` with 100% coverage
5. ✅ All tests passing (100% pass rate)
6. ✅ All interactive elements have `data-testid` attributes
7. ✅ Page passes WCAG 2.1 Level AA accessibility validation (axe-core)
8. ✅ Page is responsive across 3 breakpoints (mobile, tablet, desktop)
9. ✅ Pull Request reviewed and approved
10. ✅ Pull Request merged to `develop` branch

**NOT required for "migrated" status**: Backend integration (can use mock data initially)

### Backend Connected

A page is considered "backend connected" when ALL of the following criteria are met:

1. ✅ Service layer created in `src/services/<entity>Service.ts`
2. ✅ React Query hooks created in `src/hooks/`
3. ✅ Page component updated to use real data (no mock data)
4. ✅ Data transformations implemented (backend DTOs → frontend types)
5. ✅ Error handling implemented with user-friendly Portuguese messages
6. ✅ Loading states implemented with spinners/skeletons
7. ✅ Data validation matches legacy system rules
8. ✅ Calculations verified correct (totals, averages, aggregations)
9. ✅ Integration tested in QA environment with real backend
10. ✅ Service layer unit tests passing
11. ✅ Page integration tests passing (optional but recommended)
12. ✅ Pull Request reviewed and approved
13. ✅ Pull Request merged to `develop` branch

### Critical Routine Complete

A critical routine is considered "complete" when ALL of the following criteria are met:

1. ✅ All pages in routine are "migrated" (frontend complete)
2. ✅ All pages in routine are "backend connected" (real data)
3. ✅ E2E test created covering full routine workflow
4. ✅ E2E test passing in CI/CD pipeline
5. ✅ Side-by-side validation with legacy system (functionality parity)
6. ✅ QA team approval
7. ✅ Stakeholder sign-off
8. ✅ Production deployment approved
